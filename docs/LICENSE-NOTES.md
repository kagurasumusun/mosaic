## The license

`LICENSE` in the repository root is the whole of the project's license: the
**brain-emu License, version 1.0** (`SPDX-License-Identifier:
LicenseRef-brain-emu-1.0`, or `LicenseRef-brain-emu-1.0` where a scan wants no
SPDX prefix at all).

It was written for this project rather than adopted from an existing one, which
is why it is not MIT, BSD or Apache-2.0 with a different name: the intent is
that this tree is under terms the project owner chose, with the reasoning
visible in the text.

It is a permissive license, in the sense that matters here:

* you may use, copy, modify, redistribute and sell the code, including in
  closed products, and the permission is perpetual and irrevocable as long as
  the conditions are met;
* the conditions are attribution (keep the notices and the identifier), shipping
  the license text, saying that you changed the code, not implying endorsement,
  and not using the authors' names as a product name;
* there is a patent grant with the usual defensive termination - if you sue over
  a patent the code infringes, you lose the license;
* the permission is in terms of copyright and patents only. It grants nothing
  in the ARM or NXP trademarks, and it does not cover `reference/` (below).

Two practical notes, because they are the kind of thing a license file is not
the right place to say:

* **If the project owner wants different terms later, they can simply replace
  `LICENSE`.** The copyright holder is not bound by the license they hand out -
  as long as the notice and the old text stay with copies of what was already
  distributed, the terms for new releases can change.
* Nothing here is legal advice, and no lawyer has read it. A short license with
  clear intent is easier to fix than a long one that was never checked, and
  every condition in it is one a reader can verify by looking at the tree. If
  the project is ever sold, or a company wants to depend on it under a policy
  that only accepts OSI-approved licenses, that is the moment to have it
  reviewed - the text is short enough to review.

## Where the code's copyright comes from

Everything under `src/`, `include/`, `tools/` and `tests/` was written for this
project, from the ARM architectural and Technical Reference Manuals in
`reference/`. No file is a copy of somebody else's source, and no file carries a
third-party license header. Where a constant or a table was transcribed from a
document, the comment names the document and the section, so the number can be
checked rather than trusted. The copyright holder is whoever the project owner
designates; the files say "the brain-emu authors" so that the notices stay true
before that name is filled in.

## `reference/`

`DDI0198E_arm926ejs_r0p5_trm.pdf` (ARM926EJ-S TRM), `DDI01001.pdf` (ARM ARM) and
`IMX28CEC.pdf` are Freescale/NXP and ARM documents. They are kept here as the
normative references this code is written against, so the code can be checked
against them offline, and they are *not* redistributable under the terms ARM and
NXP publish them on: a source or binary package must drop `reference/` (the
CMake/Make builds never read it). This is stated in section 6 of `LICENSE` as
well, because the two facts together are easy to get wrong - the code is ours to
license, the manuals are not. Comments cite the manuals by section rather than
quoting them (`DDI 0198E 2.3`, `TRM table 3-9`, and so on), so a reviewer can
look up a number instead of trusting it.

## The instruction corpus

`tests/data/corpus.txt` is generated by `tests/gen_instr_tests.py`, which drives
Unicorn (whose ARM core is QEMU's, GPLv2) for execution and Keystone for
assembly. Two consequences worth understanding:

* The *content* of a corpus line is a fact about a machine state transition - an
  instruction word plus the register and memory contents that result. Facts of
  that kind are not the expression of either program, and the generator never
  copies source, only observed values.
* The generator itself is original to this project and covered by the same
  license as the rest of the tree; Unicorn/Keystone are development-time
  dependencies (as a compiler or an assembler is), not linked into the emulator,
  so the library and the tools stay free of GPL code. `make check` does not need
  them: the corpus is checked in as data, and the two Python tests that *do* use
  Unicorn/Capstone skip themselves with a message when those are not installed.

## Third-party code copied into this tree

None. Everything under the active source tree is written here, including the two
code generators (`arch/arm/cpu/classic/arm9/arm926ej-s/jit/backends/x86_64/emit_x64.cpp` and

encoders they emit through, the decoders, and the C API.
