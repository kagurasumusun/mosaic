# Licensing notes

Nothing in this tree has been assigned a licence text yet, so no file carries a
`SPDX-License-Identifier` header: each one instead carries a one-line
`SPDX-file-note` pointing here. The project owner has to pick the licence before
a `LICENSE` file can be added; adding one on a guess would be worse than
leaving it visibly open.

What does need recording is where the *inputs* come from, because they constrain
what the result can be.

## `reference/`

`DDI0198E_arm926ejs_r0p5_trm.pdf` (ARM926EJ-S TRM), `DDI01001.pdf` (ARM ARM) and
`IMX28CEC.pdf` are Freescale/NXP and ARM documents. They are kept here as the
normative references this code is written against. They are tracked here so the code can be
checked against them offline, and they are *not* redistributable under the terms
ARM and NXP publish them on: a source or binary package must drop `reference/`
(the CMake/Make builds never read it). Comments cite them by section rather than
quoting them (`DDI 0198E 2.3`, `TRM table 3-9`, and so on), so a reviewer can
look up a number instead of trusting it.

## The instruction corpus

`tests/data/corpus.txt` is generated by `tests/gen_instr_tests.py`, which drives
Unicorn (whose ARM core is QEMU's, GPLv2) for execution and Keystone for
assembly. Two consequences worth understanding:

* The *content* of a corpus line is a fact about a machine state transition — an
  instruction word plus the register and memory contents that result. Facts of
  that kind are not the expression of either program, and the generator never
  copies source, only observed values.
* The generator itself is original to this project and is covered by whatever
  licence the project picks; Unicorn/Keystone are development-time dependencies
  (as a compiler or an assembler is), not linked into the emulator, so the
  library and the tools stay free of GPL code.

`tests/test_instr.cpp` compares this core against those recorded values, and
`make check` does not require Unicorn, Keystone or Python: the corpus is checked
in as data so the test is reproducible offline.

## Third-party code copied into this tree

None. Every file under `src/`, `include/`, `tools/` and `tests/` is written
here. Where an encoding table or a fault-status value was transcribed from a
document, the file's comment names the section, so a reviewer can check the
number rather than trust it.
