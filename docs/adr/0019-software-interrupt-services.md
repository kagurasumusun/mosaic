# 0019: ソフトウェア割り込みはサービスとして外から答える

状態: 暫定採用。PC ファームウェアは暫定であり、ROM の代わりではない。

根拠: 設計書 §12.1、ADR 0001、ADR 0018。実測は `tests/`（ADR 0022 のブートマトリクス）。

## 背景

PC のファームウェア境界はソフトウェア割り込み表そのものである。実モードの
ブートローダは `INT 13h` で CD を読み、`INT 10h` で画面に書き、`INT 15h` で
メモリ量を尋ね、自分がフックしたベクタの旧ハンドラを呼び出す。Unicorn は
`INT n` を配送しない（ADR 0018）ので、この境界をどこに置くかを決める必要が
ある。BIOS ROM を丸ごと動かす道（SeaBIOS）は、PCI・ACPI・SMM まで必要で
この段階の費用に見合わない。

## 決定

- `InterruptService` を CPU エンジンの外のポートにする。`INT n` のたびに
  `service(vector, &mut dyn SoftwareInterruptCpu)` が呼ばれ、`true` を返せば
  ゲストは `INT` の次の命令から続く。`false` はゲスト自身のハンドラに
  譲ることを意味する。
- サービスの実装は `pc` マシン側（`apps/system/src/pc_boot.rs`）に置く。エンジンは
  「誰が答えるか」を知らない。
- 低メモリに実機と同じ配置を用意する。IVT の全 256 エントリが `F000h` の
  トランポリン（`INT n; IRET`）を指し、BDA（`0040h`）に機器ワード・
  メモリ量・ビデオ状態・固定ディスク数を置く。旧ベクタへ連鎖するローダは
  このトランポリンに落ち、そこで `INT` が再びサービスに入り、`IRET` で戻る。
  ゼロを指したベクタは無い。
- 起動点へは `JMP FAR` スタブで入る（ADR 0018 の実測 2）。
- 現時点のサービス範囲: `INT 10h` テレタイプ/文字列/モード/カーソル、
  `INT 11h`/`12h`、`INT 13h` の CHS・EDD 読み出し・拡張パラメータ・
  El Torito（`AH=4Bh`）、`INT 15h` の `2400h`/`8800h`/`E801h`/`E820h`、
  `INT 16h`、`INT 1Ah`。範囲外のベクタは「答えない」と明示する。

## 受け入れ基準

- 実 ISO（Tiny Core）の isolinux が自分自身のコードを実行し、CD を検出し、
  El Torito のスペックパケットを取得し、バナーを VGA テキスト窓に出す。
- 合成ブートセクタで `INT 10h` の文字が画面に、`INT 13h` の読み出しが
  ディスク読み出し記録に出る。
- 未対応ベクタは `unhandled_interrupt` に残り、無言でハングしない。

## 実測で分かったこと（Linux カーネルを起動して）

Tiny Core 6.6.8 の `vmlinuz` を i386 ブートプロトコルで起動すると、次の順に進む。

1. セットアップの実モードコードが走り、`INT 15h E820` などでファームウェアを呼ぶ。
2. 保護モードへ移り、デコンプレッサが自分自身を再配置する（`rep movsl` で 5.4 MB）。
3. 再配置後、線形 `0FF7Ch` で停止する。`EAX=FFF00000h` という未マップの
   ポインタを触ったためで、`boot_params` のどこかが未初期化のまま渡っている疑いがある。

ここで分かった落とし穴は 2 つ。どちらも「ファームウェアが実モードの規約を
保護モードのゲストに適用してしまう」という同じ形をしている。

- `boot_params` の `E820` 表（`90000h+2D0h`）はカーネル自身の実モードコードと
  重なる。ローダが書くと `intcall` を踏み潰し、カーネルはメモリマップをコードとして
  実行する。表はカーネルが `INT 15h` で取りに来るので、ローダは書かない。
- `DS`/`ES` は保護モードではセレクタであって段落番号ではない。`×16` を続けると
  ファームウェアの応答が段落サイズの番地に書かれ、ゲストは別の場所を読む。
  `CR0.PE` を見て base 0（フラット）に切り替える。

## まだ主張しないこと

- BIOS ROM の代替ではない。オプション ROM スキャン、PCI 列挙、
  VGA のグラフィックスモード、キーボード入力、時刻の進行は未実装。
- isolinux の第 2 段まで到達することは確認済みだが、カーネル起動は未到達。
- 保護モードのゲストが設定した IDT 経由の配送は、アダプタ側の実装待ち。
