# 0003: u64 ピコ秒と決定論

状態: 暫定採用。根拠: 構成設計書 §12.4, §13.2。

VTime は u64 ピコ秒。約 213 日で上限に達するため、加算は checked operation とし、
暗黙の wrap や飽和を禁止する。長期間のシナリオで不足する場合は、安定化前に再検討する。
ホストの実時間をモデルから直接参照しない。

採用方針: 単一スレッド、固定順のコア実行、イベントは (time, insertion sequence) 順。
過去への予約、時刻・sequence・EventId のオーバーフローをエラーにする。
量子は P1 の実測後に決める。命令数を物理的なサイクル精度として扱わない。

実装済み: VTime、checked_add、EventQueue、ModelContext と境界・決定論テスト。
未実装: CPU スケジューラ、clock tree、実時間同期。

EventId を挿入 sequence と兼用し、同時刻では挿入順で dispatch します。
取り消した ID は再利用しません。ID カウンタが u64::MAX に達すると新規予約を拒否します。
予約数は capacity で制限し、過去時刻・容量不足・カウンタ枯渇時は状態を変えません。
`pop_next` が時刻を進め、`pop_due(until)` は期限以下のイベントを 1 件ずつ返し、
残りがなければ until まで進めます。イベントを飛び越える単純な時刻変更 API は公開しません。
無限のゼロ時間再予約はキューだけでは防げないため、呼び出し側の実行予算で制御します。
